# OCR/VLM combination implementation plan

> **For agentic workers:** Use superpowers:executing-plans or subagent-driven-development; preserve the fixed policies and record any deviation.

**Goal:** Test vote-like combinations and sync reproducible code/results/web to the private repository.

**Architecture:** A pure decision module combines frozen records without labels. A replay CLI validates full aligned inputs, writes standalone experiment JSON and a paired report. The existing local page displays combination results and branch/vote evidence. No inference dependency is needed to replay cached predictions.

**Tech Stack:** Existing Python, JSON, stdlib statistics and buildless local web UI.

**Spec:** docs/superpowers/specs/2026-10-30-ensemble-design.md

## Global constraints

- No query ground truth in the decision functions; no weight/threshold search on these 44 queries.
- Preserve existing labels, catalog, baseline and five measured input runs.
- All policies report 44 queries; malformed or misaligned sources fail rather than silently reducing denominators.
- VLM abstention is not its inherited baseline Top-1 vote; its elapsed time is still charged if called.
- Replay timing is explicitly estimated from stages, not an end-to-end service benchmark.

## Review focus

- Tied or correlated votes must follow the declared deterministic rules.
- Unique strong OCR must agree with fused Top-1 and be free of cross-view conflicts before skipping VLM.
- Abstaining/invalid VLM outputs must not vote or override the new OCR.
- Cache/source records with duplicate files, different labels or missing queries must fail.
- Web evidence must distinguish a consulted VLM from one the route never called.
