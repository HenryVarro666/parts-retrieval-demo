# 同一元件多图识别

用户已授权：加入同一元件多图上传，融合逐图 OCR、形状、视觉信息，展示逐图依据，对比单图与三图结果和耗时，推送现有 GitHub 私有仓库。

## 范围与实现选择

- 沿用 Python、SQLite、RapidOCR / EasyOCR、SigLIP、可选本地 Qwen3-VL，以及无构建步骤的网页。接收 1–3 张同一实物的照片；单图和旧检索方式继续可用，旧方式只支持单图。
- 每张独立运行现有候选流程；不拼接跨照片字符构造型号。融合逐图 SQL / 图像名次及可用形状名次。强别名保留进 Top-10，冲突显式展示，禁止冲突时直接接受。
- 完全相同的解码像素只处理一次。非常相近的缩略图合并计票，每个相似组的总权重为一；保留各图原始证据和关联说明。这些阈值是固定工程规则，未经本数据集调参。
- 单图保留现有排序行为。多图以分组归一化的 k=60 RRF 融合；强别名先按独立组支持排序，再按融合分数排序。不同拍摄角度的形状可能不同，未知形状不贡献分数，不估计实际尺寸、引脚数量或封装。
- 可选 VLM 同时查看各独立图片和候选参考图；只能在冻结候选中选取或弃权。多图的直接接受要求至少两个独立组支持同一强型号且没有跨图/图内冲突；否则调用本地 VLM。原始 OCR 和型号不翻译，模型分析继续随中英西语言切换。
- 为上传批次执行两个独立流程：第一张单图，以及全部照片融合。逐图 OCR 不在两次流程间复用；共享已经加载的检索模型和参考索引。分别测实际墙钟耗时，包括所请求的 VLM 子进程/加载；单列初始化、整个对照请求耗时，明确单图先执行的预热顺序。实时 VLM 使用新命名空间，禁止历史输出充当新实测。
- 网页显示可切换的图片/OCR 框、逐图文字、SQL/外观候选、形状、耗时、相似/重复标识、融合支持，以及单图/多图 Top-3/Top-10 和耗时。可选已知型号仅在浏览器评分，绝不传入推理。
- 每图上限 10 MB / 16 MP，最多三图；整体请求上限按三图扩展，逐图和总像素预算先验证后启动模型。不支持的多图旧检索配置应拒绝，不能静默忽略图片。

## 实验与证据

- 不改写历史 44 图实验、标签、别名或已有原始图。真实配对评估必须具有同一实物三图清单、型号、分组来源说明及图像哈希。推理只接收图像，标签只在评分层使用。
- 现有数据没有同一实物分组，已向用户索取本机目录。未取得真实配对时，完成 44 图的三次重复输入控制实验和联合视觉输入冒烟实验，公开标注“重复输入 / 非真实多角度”，真实多角度样本数为零，不能报告多角度准确率提升。
- 新结果单独保存到 `results/multi_image/`，网页单独展示其状态，不混入旧 44 图实验表。提供 CLI，其他机器可运行真实三图清单并重建报告。
- 验证有效融合、强型号冲突、重复与近重复、无文字/无形状、候选约束、输入拒绝、三语切换、逐图切换、失败恢复、缓存来源和计时边界。独立审查后修复实质问题，再同步私有远端并验证干净克隆。
