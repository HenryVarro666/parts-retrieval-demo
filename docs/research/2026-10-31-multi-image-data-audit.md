# data/ 中的同一实物多图核对

核对范围：现有 `manifest.csv` 209 条来源元数据、`curation.csv` 既有复核记录、重复分组线索和候选原图。目视查看了 20 张主要候选缩略图，并打开 80286 三张原图逐一核对。没有修改原图、原标签、别名或旧实验。

## 纳入：一个探索性三图组

`I80286/158840809.jpg`、`158840810.jpg`、`158840814.jpg`：同一作者 Sgroey 在 2025-01-31 的连续摆拍，来源分别记录 14:33:46、14:31:06、14:29:00。[五枚芯片图](https://commons.wikimedia.org/wiki/File:Intel_chips_286_386_387_486_pentium_size_comparison_01.jpg)、[四枚芯片图](https://commons.wikimedia.org/wiki/File:Intel_chips_286_386_387_486_size_comparison.jpg)、[三枚芯片图](https://commons.wikimedia.org/wiki/File:Intel_chips_286_386_486_size_comparison.jpg)。

三图最左侧 N80286-10 的 SX004、下方批次行、角部模具印记和磨损位置相符，支持“同一实物”假设。这是助手目视及来源一致性推断，未经物主或元件专家确认；型号标签也不构成新的专家金标准。图像主要改变取景/大小，角度差异有限，不能代表充分的多角度拍摄集。

原图包含其他 CPU，因此固定裁剪最左侧目标，避免把其他芯片文字混入识别。裁剪坐标分别是 `[20,125,146,275]`、`[24,128,193,326]`、`[15,170,245,408]`。脚本 `scripts/prepare_multi_image_fixture.py` 从原始像素重建 PNG，记录父图哈希、坐标、作者、CC BY-SA 4.0 及来源链接。没有合成新角度或放大补字。清单明确标为 `exploratory_same_object`。

## 未作为三图评估的线索

| 系列 | 核对结论 |
|---|---|
| LM317 `127532396/397` | 既有记录及目视支持同一元件正面/斜面，只有两张；没有复制一张凑三张。 |
| ESP8266 `67098451/454` | 同一蓝色 ESP-01 模块、丝印/闪存标记一致，只有两张。 |
| ESP32 `97701682/117048431` | 后者是裁剪衍生图，不是新拍摄角度。 |
| UA741 `31580116/119/124/125` | 同一拍摄会话不等于同一元件；其中一张可见 LF412CP，且有多元件/倒置图，排除。 |
| LM317 `1677084` TO-220 四视图 | 来源描述的是 TO-220 元件的角度图；画面混有 L7805CV 与 LM317T，不能当同一型号/实物四角度。[来源](https://commons.wikimedia.org/wiki/File:TO-220_Package_Four_Different_Projections.jpg)。 |
| Neo-Geo、IBM 5150 整板系列 | 同一主板多视角线索存在，但单张含多个不同芯片、目标不突出。没有用整板型号标题推断某一芯片的专家标签。 |

`curation.csv` 的 `group` 原本还用于相同来源/背景去重，组内可能是不同实物、封装或型号，不能直接当作同一元件 ID。重复输入控制实验另取原 44 查询图，每张重复三次，只验证重复处理，不当真实多角度数据。

当前结果：一个探索性三图组，零个物主/专家确认的三图组。未来需补充更多实物的真实配对拍摄，才能判断多图是否提高准确率。
