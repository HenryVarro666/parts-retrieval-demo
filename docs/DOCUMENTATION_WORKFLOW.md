# 问题、改进和交接如何保存

用户要求：每次遇到的问题和改进，包括此前、当前和将来，都要保存到文档并做好对接。下列约定将该要求落实到文件；不依赖聊天记忆。

## 四个入口

- [总目录](README.md)：所有记录的导航。
- [问题与改进台账](ISSUES_AND_IMPROVEMENTS.md)：稳定ID、现象、改进、状态及证据链接。
- [当前交接](HANDOFF.md)：现状、未解决项、下一步、正在工作的项目/分支。
- `docs/research/YYYY-MM-DD-主题.md`：每次实质尝试的详细经过、输入、命令和结果；已有原始JSON/图表为证据，不复制改写模型输出。

## 更新时机

| 时机 | 必须保存的内容 |
|---|---|
| 开始 | 基线、目标、输入/代码版本、关联问题ID、计划怎样判断改善和退化 |
| 发现新问题 | 可复现触发、实际现象、受影响样例；根因未证实就标“假设” |
| 尝试后 | 实际改动、失败尝试、运行命令、结果路径、时间和错误；未运行就明确写未运行 |
| 修复后 | 前后同输入对照、测试、模型/浏览器实测范围、新增误检/退步和残余问题 |
| 结束/交接 | 更新台账、当前交接、目录；记录实际提交/远端同步状态及下一条可执行任务 |

## 可直接复制的记录模板

```markdown
# YYYY-MM-DD：问题或改进名称

- 关联ID：PR-xxx（跨项目问题另加工程前缀）
- 状态：待验证 / 已复现 / 已实现未验证 / 已验证 / 部分改善 / 遗留
- 工程、分支、代码提交：
- 输入manifest / 文件哈希 / 数据分区：
- 模型revision、配置、硬件与依赖：

## 问题与复现
预期是什么、实际是什么、具体样例/命令/日志/截图在哪里。

## 原因与尝试
区分已证实原因和假设；保留尝试失败及放弃理由。

## 实际改进
改了哪些模块/规则；哪些结论需要新实验验证。

## 验证与前后对照
固定输入、比较对象、指标和分母、冷/暖机/加载/缓存口径。
列出纠正、退步、新增误检、失败和拒答；没有真值时不填准确率。
测试/模型实跑/浏览器/新克隆分别记录命令、结果路径及观察时间。

## 剩余问题与下一步
具体阻塞、未验证配置、下一次如何继续；更新台账/交接/目录的链接。

## 保存与同步
实际输出目录、来源许可、提交、远端/分支；未同步则明确写出。
```

## 历史与事实边界

- 旧报告不删除、不悄悄重写成最新状态。过时入口加日期及“历史快照”说明，指向新的权威记录。
- 设计建议、实现、测试通过、真实模型效果、实物/专家确认和发布是不同状态。补录历史时注明依据来自已保存记录，不伪造当时未记下的错误日志、命令或时间。
- 输入、代码或模型变更后开新运行目录；保留原对照和模型原文。说明修复是否仅改展示/来源验证，还是实际重跑了模型。
- 准确率必须列分母/样本单位/分区；三图、视频帧、重复控制分别说明。点数和任务成功状态不是三维质量指标。
- 尺寸记录必须有单位、尺度依据、独立实测真值及误差。模型预测“米”或一条已知长度校准不等于所有几何都准确。
- 文档可记录本地原始产物路径和校验信息。元件仓库已有许可的公开数据可按现有规则入库；三维工程的照片/权重/结果遵守其独立忽略规则，不能为“存档”跨项目复制或强行提交。
- 归档是项目内的文件工作；不自动创建提醒、外发消息、改变其他工程分支或授予未来发布权限。
